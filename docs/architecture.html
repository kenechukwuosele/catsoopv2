CU Quiz App — Architecture Reference

A Covenant University quiz platform built on top of the CatSooP LMS (v19.0.6). Two cooperating services — CatSooP for content rendering and FastAPI for quiz logic — combine with AI hint generation, real-time engagement monitoring, face authentication, and a gamification layer.

CatSooP :7667 FastAPI :8000 SQLite ChromaDB Ollama LLM face-api.js WebSocket

What This System Does

CatSooP (port 7667)

  • Renders .catsoop course pages
  • Authenticates students (PBKDF2 login)
  • Grades quiz submissions natively
  • Writes binary cslog files (scores)
  • Executes embedded Python blocks per-request

FastAPI (port 8000)

  • Admin panel for question/course management
  • AI hint generation (RAG + Ollama)
  • Gamification: XP, streaks, badges, leaderboard
  • Face biometric authentication
  • Real-time WebSocket room manager
  • Engagement monitoring (webcam + affect)

CatSooP Layer

CatSooP is an open-source LMS that renders course content from .catsoop files — Python-embedded HTML templates. It handles authentication, quiz grading, and binary log storage.

Request Flow Through CatSooP

sequenceDiagram participant B as Browser participant W as wsgi.py participant D as dispatch.py participant L as loader.py participant H as default handler participant A as __AUTH__/login participant CS as cslog.py B->>W: HTTP GET /Physics/week1/quiz W->>D: route(path) D->>D: resolve URL to courses/Physics/week1/quiz.catsoop D->>L: load(file_path, context) L->>A: check session / login state A-->>L: cs_user_info (username, role, email) L->>L: exec Python blocks, inject cs_username etc L->>H: render(context, html_output) H-->>B: full HTML page response Note over B: Student submits answer B->>W: POST /Physics/week1/quiz (answer) W->>D: route to quiz handler D->>L: evaluate answer via __QTYPES__ L->>CS: append score to problemactions.log CS->>CS: lzma-pickle dict, write 8B+data+8B H-->>B: result HTML (correct/incorrect)

The .catsoop File Format

Every page in the system is a .catsoop file — plain text with interspersed Python blocks and HTML.

<python>
cs_content_header = "Lecture 1: Newton's Laws"   # page title
# All cs_* variables set here are available to CatSooP
# cs_username, cs_user_info are injected automatically by CatSooP
import jwt
token = jwt.encode({"sub": cs_username, "is_admin": False}, SECRET, "HS256")
print(f"<script>window.__CU_TOKEN = '{token}';</script>")
</python>

<!-- Regular HTML follows -->
<h1>Newton's Laws</h1>
<p>Content here...</p>

<!-- Native CatSooP question block -->
<question multiplechoice csq_name="q_abc123">
csq_prompt = "What is Newton's first law about?"
csq_options = ["Inertia", "F=ma", "Action-Reaction"]
csq_soln = 0
</question>

cslog Binary Format

All grades and authentication data are stored in CatSooP's binary log format.

Format per entry: [8-byte LE length] [LZMA-compressed pickle dict] [8-byte LE length] — repeated N times. The same 8-byte length appears before and after each entry (for bidirectional traversal). 
# Grade data in a submit entry looks like:
{
  "action": "submit",
  "username": "johndoe",
  "scores": {"q_abc123": 1.0, "q_def456": 0.0},   # 0.0–1.0 per question
  "time": 1717027200.0
}

# Paths:
# Grades:  _logs/_courses/{course}/{username}/{week}/quiz/problemactions.log
# Auth:    _logs/_logininfo/{username}.log

JWT Structure

ClaimValueNotes
subusername stringUsed as identity in all API calls
is_admintrue / falsetrue for admin panel and lecturer logins
expnow + 8 hoursStandard expiry
iatnowIssued-at

Two token minting paths:

  • Student quizzes: The <python> block in quiz.catsoop calls PyJWT with CU_QUIZ_SECRET and injects the token as window.__CU_TOKEN. A fetch interceptor then auto-attaches Authorization: Bearer <token> to every API call.
  • Admin panel: POST /admin/login returns a JWT which is stored in localStorage. auth.js attaches it on every fetch via its own interceptor.

ChromaDB Vector Store (_vectors/)

Two HNSW (Hierarchical Navigable Small World) collections:

  • course_content — chunks of .catsoop lecture/problem files, 384-dim embeddings
  • qa_pairs — question text + answer + hints formatted as documents

Embeddings produced by all-MiniLM-L6-v2 (sentence-transformers). Falls back to MD5-based pseudo-embeddings if the model is unavailable.

Gradebook Access Control

Access to /{course}/gradebook is granted if the user satisfies any of:

  1. Username is in CU_QUIZ_ADMINS environment variable
  2. CatSooP cs_user_info["role"] == "Instructor"
  3. GET /{course}/is-lecturer?username= returns {is_lecturer: true}

WebSocket Authentication

The /ws endpoint requires a ?token= query parameter. The token is validated before accept() is called. PUSH_HINT and INSTRUCTOR_MESSAGE message types are rejected unless ws_is_admin is true in the decoded token.

CatSooP Password Scheme

Registration uses a two-hop hash to prevent server exposure of the raw password:

  1. Client computes: PBKDF2-HMAC-SHA256(password, password+username, 100000, 32) — hex digest
  2. Server stores: PBKDF2-HMAC-SHA512(client_hash, random_salt, 500000)

The FastAPI admin login verifies CatSooP instructors by replicating this exact chain in _verify_catsoop_instructor() in routes/admin.py.

What generate_native_quiz() Produces

The most important generator. Every call to add or delete a question triggers a full regeneration of quiz.catsoop with these sections in order:

  1. Python header — mints JWT from cs_user_info, injects window.__CU_TOKEN, window.__quizQuestionNames, window.__course, window.__week; sets up fetch interceptor
  2. CSS styles — question margins, hint containers, XP badge, timer bar, affect panel
  3. Face-auth overlay (#__face-auth-overlay) — shown before quiz; includes video feed, enroll/verify UI, retry logic
  4. Quiz start screen (#quiz-start-screen) — hidden until face auth passes
  5. Timer bar — sticky countdown (only when time_limit_minutes > 0); start time saved to localStorage
  6. Native <question> blocks — one per question; graded by CatSooP natively
  7. Mark as Done button — sends QUIZ_DONE WebSocket + triggers __triggerQuizDone()
  8. Hint JS — fetches from /admin/hints/{c}/{w}/{csq_name}, shows progressive hints
  9. XP badge widget — bottom-left pill: ⭐ XP / 🔥 streak; expandable to show rank + badges
  10. Affect widget — from generate_affect_script(); webcam + face detection loop

Gamification System

XP, streaks, and badges are awarded when a student completes a quiz (POST /{course}/{week}/quiz-complete). The system is fully idempotent — re-submissions on the same day update streaks but award no extra XP.

XP Formula

base_xp    = round(percent_correct * 100)   # 0–100
streak_bonus = min(streak * 10, 50)          # 10, 20, 30, 40, 50 (capped)
total_xp   = base_xp + streak_bonus

# base = 80, bonus = min(40, 50) = 40 → total = 120 XP

Refactor Summary (June 2026)

Three areas were refactored for maintainability. No behavior was changed.

1 — admin.js Split (1180 lines → 8 modules)

The monolithic api/static/admin/admin.js was split into 8 focused files loaded in dependency order via plain <script> tags in admin.html. All functions remain global — no bundler, no ES modules.

WasNow
admin.js (~1180 lines, everything)auth.js, ui-core.js, courses.js, questions-hints.js, monitoring.js, gamification.js, students.js, app.js
The startup IIFE and initApp() were moved to app.js (loaded last) because they call functions from courses.js — those must exist before the IIFE runs.

2 — routes/admin.py Split (monolith → 4 focused files)

Live-file routes, face-enrollment routes, and the repair route were extracted from admin.py into their own files. Each new file has its own get_db() function to support per-module dependency_overrides in tests.

Bug Fixed During Refactor

mint_token() signature mismatch — The refactored admin.py was calling mint_token({"sub": "admin", ...}) (passing a dict) but api/auth.py defines mint_token(username: str, is_admin: bool). This would have caused a TypeError on every admin login in production. Fixed by changing all 4 call sites to mint_token("admin", True) / mint_token(lec.username, True).
